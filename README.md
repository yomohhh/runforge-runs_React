# Runforge: страница Runs

Страница для просмотра запусков AI-агентов: список, поиск, фильтр по статусу и подробности запуска с логами и результатом. Данные приходят из локального mock-сервиса (Promise с задержкой), как будто от backend.

**Стек:** React 19, Vite, TypeScript, CSS Modules, Vitest + React Testing Library.

## Как запустить
    npm install
    npm run dev

Демо-сценарии, добавляются в адрес:
- `?demo=slow` долгая загрузка
- `?demo=error` ошибка с кнопкой "Повторить"
- `?demo=empty` пустой список

## Проверки

    npm test            # автотесты
    npm run typecheck   # проверка типов
    npm run lint        # ESLint
    npm run build       # production-сборка

## Что реализовано
- **Список запусков:** название, репозиторий и ветка, статус, дата создания, длительность (если известна). На экранах от 360 px таблица заменяется карточками.
- **Фильтр по статусу** (Все, Queued, Running, Succeeded, Failed) с заметным активным состоянием и счётчиками.
- **Поиск** по названию и репозиторию без учёта регистра; работает вместе с фильтром.
- **Состояния данных:** скелетон при загрузке, ошибка с кнопкой повтора, пустой результат с кнопкой сброса фильтров.
- **Детали запуска** в боковой панели (drawer): метаданные, логи с подсветкой ошибок, результат. Закрыть можно крестиком, кнопкой «Вернуться к списку», кликом по фону или клавишей Esc.
- **Статусы** различаются не только цветом, но и текстовой подписью.
- Если нет длительности, результата или логов, интерфейс показывает понятную подпись.

## Почему так сделано
- **Mock-сервис с `AbortSignal`:** запрос можно отменить при повторе или уходе со страницы, поэтому устаревший ответ не перезапишет состояние. Замена на настоящий `fetch` не потребует менять остальной код.
- **Состояние загрузки как объединённый тип** (`loading | success | error`): компилятор не даёт обратиться к данным, пока они не загружены.
- **Состояние страницы в `App`, остальное в компонентах:** `RunFilters`, `RunList`, `RunDetails` получают данные пропсами и сами ничего не хранят.
- **Drawer через портал** с `inert` на корне приложения, возвратом фокуса и ловушкой Tab: панель удобна с клавиатуры и скринридера.
- **Логика фильтрации в чистой функции `filterRuns`**: её легко тестировать отдельно.

## Структура проекта

    src/
      app/           App: состояние страницы и сборка компонентов
      components/
        layout/      Header, Sidebar
        runs/        RunFilters, RunList, RunDetails, LogLines, StatusBadge
        ui/          Drawer, Icon, DataStates (скелетон и ошибка)
      data/          mock-запуски
      services/      runService: имитация запроса к backend
      hooks/         useRuns (загрузка, повтор, отмена), useCompactLayout
      utils/         filterRuns, форматирование дат и длительности
      types/         модель данных Run
      test/          автотесты
